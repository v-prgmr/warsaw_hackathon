AR GLASSES BRIDGE - SETUP FOR THE UBUNTU LAPTOP CONNECTED TO THE G1
====================================================================
(repo v-prgmr/warsaw_hackathon, branch claude/ar-glasses. Details: g1_ws/src/g1_ar_bridge/README.md,
 ar_glasses/README.md, AGENTS.md section 27)

WHAT THIS IS
------------
The Snap Spectacles already have the Dimensional OS Lens installed (pushed once from Lens Studio on
Windows; it stays on the glasses). The Lens is a WebSocket CLIENT. It connects over Wi-Fi to a
SERVER, "the bridge", at

    ws://<THIS LAPTOP'S Wi-Fi IP>:8787        (port fixed in the Lens; you only type the IP)

The bridge is our ROS 2 package g1_ar_bridge. It runs on THIS laptop, in our usual ROS 2 Humble
container, next to our stack, because this laptop sees the G1's topics over Ethernet. Nothing is
installed on the robot. It is read-only: it never sends commands to the robot.

    Spectacles --Wi-Fi--> this laptop: ar_bridge (:8787)  <-- TF, /cloud_map, /plan, POI markers
                                       tag_anchor          <-- robot camera sees the wall AprilTag
                                       our stack (g1_sensors, g1_mapping) --Ethernet--> G1

No FastAPI is needed: ar_bridge is one ROS 2 node with a plain WebSocket server ("websockets"
library), which is all the Lens speaks.


HOW THE GLASSES ARE LOCATED: ONE APRILTAG ON A WALL, SEEN BY BOTH CAMERAS
-------------------------------------------------------------------------
  - tag_anchor: the robot camera sees the tag while the robot STANDS STILL 1-2 m in front of it
    -> publishes the static TF  map -> ar_tag_0.
  - The glasses see the same tag in "AprilTag" registration (they send camera frames + their pose)
    -> ar_bridge computes glasses-world <-> map and publishes map -> ar_world -> spectacles.
  - Order does not matter. If the glasses finish first, the Lens shows "Waiting for the robot
    camera to see tag 0" until the anchor exists.

THE TAG: AprilTag family 36h11, ID 0, printed >= 15 cm (A4 ideal), white paper margin kept, flat
on card, taped to the wall. MEASURE THE BLACK SQUARE (edge, metres) -> tag_black_size_m below.
Head RealSense (looks 48 deg down): tag low on the wall or on the floor ~1 m in front of the robot.
Chest OAK-D: tag at chest height (its topics and mount TF must be verified first).


1. NETWORK (once per session)
-----------------------------
- Ethernet to the robot as usual (192.168.123.x). See g1_ws/README.md section 1.
- Laptop Wi-Fi on the SAME network as the glasses. Event Wi-Fi often blocks devices from talking
  to each other -> phone hotspot or our own router for laptop + glasses.
- Wi-Fi IP of this laptop:      ip -4 addr show     (the wl... interface)
- Firewall, if on:              sudo ufw allow 8787/tcp
- Clock: sync this laptop to the robot (g1_ws/README.md section 5, AGENTS.md section 7) before
  live runs; the glasses' TF is stamped with this laptop's clock.


2. CONTAINER + BUILD (once, and after every git pull)
-----------------------------------------------------
    cd ~/warsaw_hackathon && git fetch origin && git checkout claude/ar-glasses && git pull
    ROBOT_IFACE=<your ethernet NIC> scripts/run_humble.sh      # rebuilds the image (adds websockets)
    # inside the container:
    cd /ws/g1_ws && colcon build && source install/setup.bash
    # (if another package fails to build: colcon build --packages-select g1_ar_bridge g1_sensors g1_mapping)

The container runs with --net=host, so port 8787 is reachable on the laptop's Wi-Fi.


3. RUN (each in its own terminal inside the container, `source /ws/g1_ws/install/setup.bash`)
------------------------------------------------------------------------------------------------
    ros2 launch g1_sensors tf_chain.launch.py                 # our /tf (robot -> cameras)
    ros2 launch g1_mapping mapping.launch.py static_tf:=false # map, /cloud_map, map -> odom
    # robot camera: head RealSense on the Orin with aligned depth (start_realsense.md), topics
    #   /camera/color/image_raw  /camera/color/camera_info  /camera/aligned_depth_to_color/image_raw
    ros2 launch g1_ar_bridge ar_bridge.launch.py tag_black_size_m:=0.16     # YOUR measurement

    # chest OAK-D instead (only after its topics + torso_link -> oak TF are verified):
    ros2 launch g1_ar_bridge ar_bridge.launch.py tag_black_size_m:=0.16 \
        image_topic:=<rgb> camera_info_topic:=<rgb camera_info> depth_topic:=<depth aligned to rgb>

The image's frame_id must be the camera's OPTICAL frame (e.g. camera_color_optical_frame).


4. DO IT
--------
a) Stand the robot still, 1-2 m in front of the tag, facing it. Watch:
       ros2 topic echo /ar_glasses/anchor_status
   until "state": "anchored" (log: "anchored map -> ar_tag_0 ... 'depth': 'used'").
b) Glasses: Drafts -> Dimensional OS -> Next -> type THIS laptop's Wi-Fi IP -> Registration ->
   press "AprilTag" -> look at the wall tag from 1-2 m and step sideways slowly.
   The bar fills ("Tag 0 seen N/6"), the wizard finishes, the robot box sits on the real robot.
c) Check in RViz (fixed frame map): TF shows ar_tag_0, ar_world, spectacles.
       ros2 run tf2_ros tf2_echo robot_center spectacles     # robot -> glasses, live
       ros2 topic echo /ar_glasses/status
d) POIs: anything published as visualization_msgs/MarkerArray on /ar_glasses/markers (frame map)
   appears in the glasses (TEXT = label, CUBE = 3D box). Quick check:
       ros2 run g1_ar_bridge publish_demo_pois
   Voice/typed commands from the glasses arrive on /ar_glasses/user_command (std_msgs/String).

Fallback: in the Lens press "Manual Placement", drag the marker onto the real robot, Complete.


5. TEST WITHOUT THE ROBOT (optional)
------------------------------------
No ROS needed, simulated G1 + a real tag on your wall:
    cd ~/warsaw_hackathon/g1_ws/src/g1_ar_bridge
    python3 -m pip install --user -r requirements-sim.txt
    python3 -m g1_ar_bridge.sim_main --tag-size 0.16
Glasses: same steps; the virtual G1 appears 1.5 m in front of the tag, facing it.
Tests:  python3 -m pytest g1_ws/src/g1_ar_bridge/test      (inside the container also runs the
        ROS launch test)


SAFETY (AGENTS.md sections 19 and 25)
-------------------------------------
- The bridge never moves the robot: the Lens's navigation marker and e-stop button are disabled,
  goals / joystick / e-stop messages are refused. The only e-stop is the robot's remote.
- Do NOT run the upstream Dimensional OS stack (launcher/scripts/start.sh) against the real G1:
  it is a second robot stack with its own map and it can walk the robot.


TROUBLESHOOTING
---------------
- Lens "WebSocket connection timeout": wrong IP (use the Wi-Fi IP), different Wi-Fi, firewall,
  or the Wi-Fi isolates clients (use a hotspot). From a phone on the same Wi-Fi open
  http://<laptop IP>:8787 - a short error page = reachable, spinning = blocked.
- "Waiting for the robot camera to see tag 0": the anchor is missing. Robot standing still?
  Camera topics right? TF map <- <optical frame> available (tf_chain + g1_mapping running)?
- "Robot and glasses disagree on 'up'": the robot camera's TF is wrong (mount/frame); check RViz.
- Robot box / POIs offset: wrong tag_black_size_m, or the tag moved after anchoring
  (re-anchor: stand the robot in front of it again; then re-register on the glasses).
- After a NEW mapping session (new map), re-anchor: map frames differ between sessions.


END OF A SESSION
----------------
Ctrl-C each launch, or `bash /ws/scripts/stop_ros.sh` inside the container (AGENTS.md section 19;
never kill -9 a ros2 launch).
